# PFS 数据分析 Agent · 使用说明

PFS 是一个本地通用数据分析工作台。先连接或上传数据，再用自然语言描述问题；系统会在当前权限和数据范围内检查结构、调用分析工具并返回可回看的结果。

## 快速开始

1. 在「模型」中配置一个可用的 OpenAI-compatible 模型。
2. 在「数据源」中上传 Excel/CSV，或连接受支持的数据库。
3. 先让 Agent 查看数据结构，再提出带有指标、范围和时间窗口的问题。
4. 查看工具记录、SQL、数据引用和结果状态；不要只依据一段自然语言总结。

示例：

```text
查看当前数据有哪些表和字段
比较最近三个月各区域销售额，并标注数据覆盖范围
检查订单表的缺失值和重复记录，再给出清洗建议
```

## 可用分析能力

- 数据结构、字段详情和有限行查询；
- 描述性统计、分组、趋势、异常和常见建模分析；
- 图表推荐与交互式图表；
- Excel、Word、PPT 和 Dashboard 等交付物；
- 知识库、Skills、工作区、Workflow、MCP 和后台任务。

不同能力是否可用取决于当前模型、数据源、工作区权限、依赖和部署配置。界面显示的“源码存在”不等于当前环境已经运行成功。

## 结果核验

每个关键结论都应回答：

- 使用了哪一个数据源、表和字段；
- 时间窗口、筛选条件、分母和排除项是什么；
- 结果来自哪个工具或 Artifact；
- 哪些是数据支持的事实，哪些只是待验证的解释。

如果数据不足、字段不存在、查询失败或来源冲突，PFS 会保留失败或待确认状态，不应补写一个看似合理的数字。

## 写入与导出

读取和计算优先走只读工具。创建分析表、清洗、写回外部系统、导出或启动长任务前，应确认目标、范围和结果位置。外部系统写入必须具备明确的用户意图、幂等键和可追踪记录。

## 数据安全

不要上传未经授权的个人敏感信息、商业秘密或违法内容。不要把 API Key、密码、`secret_key`、本地数据库、上传文件和生成结果提交到 Git。网页内容、MCP 返回值和模型输出均按不可信输入处理。

## 运行边界

当前版本仍在开发中。Docker、真实模型任务、SSE 长任务、恢复、外部 MCP、飞书、部署和线上验收需要在相应环境单独验证。
